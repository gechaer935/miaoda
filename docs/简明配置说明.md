# 秒答简明配置说明

本说明对应仓库当前源码。最常用的组合是：**DeepSeek + 阿里云百炼两家的 API Key**，都填在后端，桌面端和手机端不用填写模型 Key。

## 1. 需要哪些 Key

| 配置项 | 是否需要 | 用途 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 默认配置需要 | 面试回答，使用 DeepSeek API 平台的 Key |
| `DASHSCOPE_API_KEY` | 默认配置需要 | 阿里云百炼：实时语音识别、截图解题、翻译，以及面试回答备用模型 |
| `ZHIPU_API_KEY` 或 `BIGMODEL_API_KEY` | 可选，二选一 | 智谱语音/视觉备用能力；默认截图解题和实时语音链路不依赖它 |
| `MIAODA_JWT_SECRET` | 必填，自己生成 | 登录签名密钥，至少 32 个字符 |
| `MIAODA_ADMIN_TOKEN` | 使用管理后台时必填，自己生成 | 管理员初始密码，至少 32 个字符；与上面的密钥不同 |

`DASHSCOPE_API_KEYS` 是可选的多个百炼 Key，用英文逗号分隔，用于笔试请求轮换/重试。只有一个 Key 时填 `DASHSCOPE_API_KEY` 即可。

API 账号需要有额度，并开通所用模型；模型名以你账号可调用的型号为准。仓库模板默认使用 DeepSeek V4、Qwen3.7/Qwen3.6、`fun-asr-realtime` 和 `qwen-mt-lite`。如果配置智谱，Key 所属平台必须与 `ZHIPU_BASE_URL`、`ZHIPU_AUDIO_BASE_URL` 匹配，模板指向 `api.z.ai`。

GitHub/Gitee Token、服务器 SSH 私钥只用于维护者发布，**本地运行不需要**。桌面端 `.env.example` 中其他 OpenAI、Gemini、Claude 等变量属于扩展能力，运行这里的秒答主流程不用全部申请。

## 2. 配置后端

安装 Git、Node.js 22（22.12 或更高的 22.x）、Go 1.24+；需要手机网页时再安装 pnpm。Windows 桌面端原生依赖需要 Python 3、Visual Studio C++ Build Tools 和 Rust/MSVC 工具链。

在 PowerShell 执行：

```powershell
git clone <你的源码仓库地址> miaoda
cd miaoda
Copy-Item miaoda-go-server/.env.example miaoda-go-server/.env
```

编辑 `miaoda-go-server/.env`，至少替换以下值（尖括号内容是占位符）：

```dotenv
MIAODA_JWT_SECRET=<自己生成的随机密钥，至少32字符>
MIAODA_ADMIN_USERNAME=admin
MIAODA_ADMIN_TOKEN=<另一段随机密钥，至少32字符>
DEEPSEEK_API_KEY=<你的DeepSeek API Key>
DASHSCOPE_API_KEY=<你的百炼API Key>
ALLOW_MODEL_MOCK=false
```

生成随机值可执行下面的命令两次，分别填入 JWT 密钥和管理员初始密码：

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

其余先保留模板默认值，客服信息 `SUPPORT_EMAIL`、`SUPPORT_QQ`、`SUPPORT_WECHAT` 默认留空，需要时填自己的。SQLite 数据库会自动创建，无需另外安装 MySQL 或 Redis。

## 3. 启动

首次运行桌面端，先安装依赖并编译原生音频模块：

```powershell
cd miaoda-desktop
npm ci
npm run build:native
cd ..
```

然后在仓库根目录，分别开终端运行：

```powershell
.\start-backend.cmd
```

```powershell
.\start-desktop.cmd
```

可选的手机助手：

```powershell
.\start-mobile.cmd
```

首次启动会安装依赖/构建，耗时较长。后端健康检查：`http://127.0.0.1:3001/health`。管理后台：`http://127.0.0.1:3001/admin`，首次使用上面配置的用户名和 `MIAODA_ADMIN_TOKEN` 登录；改过管理密码后使用新密码。

桌面端先注册账号并登录，需要额度时在管理后台创建充值卡，再在客户端兑换。只想看界面/联调可以将 `ALLOW_MODEL_MOCK=true`，但模拟结果不代表真实模型和实时语音可用。

手机和电脑需在同一局域网，在防火墙放行局域网的手机网页端口 `5174`。手机网页通过 Vite 代理访问本机后端，无需向手机开放 `3001`。启动脚本会尝试检测电脑局域网 IP，失败时手动配置 `MOBILE_BASE_URL` 和 `ALLOW_ORIGIN`，再扫码配对。不要在公网直接开放这个开发环境。

## 4. 自建服务器时

- 所有模型 Key 只放后端 `.env`，不要放到 `VITE_*`、网页源码或桌面安装包中，也不要提交 Git。
- 本地 `start-desktop.cmd` 默认连接 `http://127.0.0.1:3001`；可通过进程环境变量 `MIAODA_API_BASE_URL` 指向自己的 HTTPS 后端。正式包中的 `example.invalid` 域名均为占位符，发布前请替换桌面端 `MiaodaAuthClient.ts` 的 API 地址、`main.ts` 和 `package.json` 的更新地址，以及外链白名单和网站链接。
- 手机网页本地开发通过 Vite 代理连接后端；自建生产环境使用同源 `/api`、`/ws` 反代。只有 WebSocket 支持构建时配置 `VITE_WS_BASE_URL`；模板中的 `VITE_API_BASE_URL` 当前未被请求代码使用。
- 网站账户页通过同源 `/api` 访问后端，手机端通过同源 `/api`、`/ws` 访问后端；可参考 `deploy/Caddyfile.example` 配置反向代理。设置后端 `ALLOW_ORIGIN` 和 `MOBILE_BASE_URL` 为自己的网页域名。客户端安装包与更新文件由部署者自行构建、托管；仓库不附带公共下载服务。

完整后端参数见 [后端配置模板](../miaoda-go-server/.env.example)。
