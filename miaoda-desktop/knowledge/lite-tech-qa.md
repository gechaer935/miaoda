# Lite 技术追问题库

## 压缩和滑动窗口，你有了解过其他的压缩方法吗？

了解。滑动窗口更像 LZ 系列压缩里的“找重复片段”机制，比如 LZ77 会在已经出现过的窗口里找最长匹配，用“距离 + 长度 + 下一个字符”来表示重复内容。除此之外，常见压缩方法还有：

1. 哈夫曼编码：根据字符频率分配不同长度的编码，高频字符用短编码。
2. 游程编码：把连续重复的数据压缩成“次数 + 值”，适合重复很多的场景。
3. 字典压缩：像 LZ78、LZW 会动态维护词典，把重复出现的字符串替换成字典编号。
4. 熵编码：比如算术编码，会更接近信息熵极限，但实现复杂度更高。

如果是在班会或面试里简短回答，我会说：滑动窗口主要解决重复子串匹配问题，其他压缩思路还包括哈夫曼编码、游程编码、字典编码和算术编码，不同方法适合的数据分布不一样。

## 滑动窗口是否有自己实现过？

实现过。通常会根据问题类型选择不同写法：

1. 固定长度窗口：维护左右边界和窗口内统计量，每次右移时加入新元素、移除旧元素。
2. 可变长度窗口：右指针扩张窗口，条件不满足时移动左指针收缩窗口。
3. 字符串类问题：会配合哈希表统计字符频次，比如最长不重复子串、最小覆盖子串。
4. 压缩场景：会在历史窗口里查找当前串的最长匹配，再输出匹配距离和长度。

回答时可以补一句：我实现时重点会注意边界条件、窗口状态更新顺序，以及左右指针移动后统计信息是否同步。

## 是否有自己实现过滑动窗口？

有实现过。最常见的是用双指针维护一个区间，右指针负责扩大窗口，左指针负责在条件不满足时收缩窗口，同时用哈希表或计数器维护窗口状态。

比如做最长不重复子串时，右指针扫描字符，遇到重复字符就移动左指针直到窗口重新合法。这个模式的关键不是模板本身，而是明确窗口里要维护什么状态，以及什么时候扩张、什么时候收缩。
